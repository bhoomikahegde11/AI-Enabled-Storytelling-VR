# Level 1 segmented NPC recording plan

## Scope and source

These six workbooks are recording plans for the existing 1,047 authored Level 1 C# templates. The C# character tables are authoritative; the generator checks every template against `../Level1_AllNPC_Dialogues.csv` and stops on a mismatch. It does not write Unity files, change dialogue, create audio, or implement playback. All recording statuses start at `PENDING`.

The `TimePressure` scenario has 19 templates in the inventory but is intentionally inactive in the current game. They remain in the sheets for completeness and are labeled accordingly.

## Workbook tabs

| Tab | Purpose |
| --- | --- |
| Dialogue Overview | One source-exact row per template, its conditions, variables, component count and ordered playback plan. |
| Static Recording Segments | One recordable fixed-text occurrence per row, including full sentences with no placeholders. Spoken text is trimmed; the manifest retains exact source whitespace and punctuation. |
| Number Library | 36 clips per character: 1–9, 10–19, tens 20–90, and hundreds 100–900. |
| Dynamic Vocabulary | 17 character-specific clips for spices, currency, units and fallbacks. Catalog-only and fallback values are labeled. |
| Assembly Manifest | One row per ordered source component, including silent separator rows. `Source_Text_Or_Placeholder` concatenates back to the original C# template exactly. |
| Recording Summary | Counts, unresolved case count and recorded/approved clip progress. |

Every static file belongs to one NPC and one dialogue occurrence: `lak_001_s01.wav`, `lak_001_s02.wav`. A repeated placeholder reuses the same number/vocabulary library rather than making duplicate vocabulary files. The prefixes are `lak`, `chi`, `sar`, `abd`, `fra`, `fat`. Number and vocabulary examples are `lak_num_20.wav`, `lak_spice_cardamom.wav`, `lak_currency_varahas.wav` and `lak_unit_seers.wav`.

## Assembly rules

Split at **every** `{placeholder}` boundary. Record each nonempty static word-bearing part as its own clip. Whitespace-only and punctuation-only parts are `SEPARATOR` rows with no WAV. For example, `I offer {counterPrice} {currency}.` has a static clip for `I offer`, a number component, a silent space separator, a currency clip, and a silent period. The manifest retains `I offer `, ` ` and `.` exactly as authored. Punctuation can guide a later timing rule but is not itself a recording.

For integers 1–999, select the hundred clip if present, then a teen or tens clip, then a unit clip: 125 = `100 + 20 + 5`, 276 = `200 + 70 + 6`. The spoken forms are “one hundred twenty five” and “two hundred seventy six”; no extra “and” clip or pronunciation variant is assumed. Zero is not needed for a valid local trade: generated buyer offers are at least one, and nonpositive offered prices fall back to the standing offer. The formatter has an invalid/empty `0 Palams` branch, which must be addressed if zero ever becomes a spoken valid quantity.

The current local session generator chooses pepper, cinnamon or cardamom, normally at 280, 560, 1,400 or 2,800 grams. The market catalog also contains clove, so each workbook lists its clip as catalog-only. The provider currently emits lowercase spice names and always uses **varahas**; the **varaha** clip is included as a singular vocabulary option but is not selected by current code. The provider can fall back to “spice” and “this lot.” Quantity units from `MarketManager.FormatTraditionalQuantity` are Seer/Seers, Veesai, Palam/Palams, Manangu/Manangus and Bahar/Bahars.

The leading part of `{quantityLabel}` can use a number plus unit clip: `2 Seers` = `num_2` + `unit_seers`. Its full runtime label also contains a parenthetical metric approximation, such as `(~560g)` or `(~1.4 kg)`. **No pronunciation rule for that suffix has been approved.** Keep its exact text in subtitles and the manifest. Decide later whether spoken dialogue omits the parenthetical or whether metric, decimal and approximation clips are required. No recording or runtime recipe for that suffix is assumed in these sheets.

`{counterPrice}`, `{currentBuyerOffer}` and `{finalPrice}` use the 1–999 number library in the current generated local market. Under the listed quantity choices, market events and personality/wealth multipliers, the maximum generated buyer cap is approximately 856 varahas. `{offeredPrice}` comes from player input and has no 999 cap; the 32 templates using it are flagged for out-of-range speech. Do not clamp or silently omit a larger number. `{ruleReply}` can be a whole sentence generated by `RuleBasedNPCBrain`, including a specific clarification question. Its 30 templates have no bounded prerecorded recipe. All such cases are listed in `Unresolved_Audio_Cases.csv`.

## Later Unity mapping

At playback time, a future adapter would select the authored `Dialogue_ID`, inspect its ordered manifest, play static WAVs, resolve number sequences and vocabulary by character, and apply separator timing. It must use the same trade snapshot and dialogue selection result that produced the subtitle. It must not independently choose another line. If a required dynamic component is unresolved or missing, a planned fallback policy must preserve the exact subtitle and conversation state; no fallback is implemented here.

The current dialogue IDs are **positional**: the audit exporter numbers templates in C# source order. An inserted or reordered template can shift later IDs and invalidate filenames even when those later sentences are unchanged. Before producing audio, freeze an ID-to-source-text mapping in version control and review any future C# reorder against that mapping. This can be done without renaming current dialogue IDs.

## Recording guidance and limitations

Record each NPC library with one consistent voice, microphone chain, speaking distance and loudness target. Preserve their authored personality and mood tags. Use a common WAV delivery format agreed with Unity audio integration (for example, mono 48 kHz PCM with consistent peak/loudness normalization); do not batch-convert or compress until the playback team sets the import policy. Trim long dead air, but retain natural consonant releases. Test joins with actual price/quantity combinations before bulk production: separately recorded fragments may expose unnatural pauses, intonation mismatches, repeated breaths or awkward plural joins. The sheets deliberately do not add grammatical variants or rewrite `a/an`.

## Regeneration

Run `python generate_recording_sheets.py` from this directory or the repository root. Python needs `openpyxl` to read existing statuses, and Node needs `@oai/artifact-tool` for XLSX authoring. Set `RECORDING_NODE` and `RECORDING_NODE_MODULES` when their installed paths differ from the Codex bundled runtime. The generator compares the C# source with the audit CSV, verifies IDs, all 34 scenarios, every assembly reconstruction, clip references, number composition, exported workbook rows and filename uniqueness. It writes `Recording_Summary.json`, the six XLSX files and `Unresolved_Audio_Cases.csv`.

On regeneration, a manually entered status is retained only when the source text, scenario/mood/patience, assembly requirements, filename and recording direction still match. A changed requirement resets the affected status to `PENDING`; a changed vocabulary word or number spelling resets that clip. The script does not infer that a generated sheet or a non-pending entry has been editorially approved.
