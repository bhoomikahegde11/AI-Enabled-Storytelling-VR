==================================================
LEVEL 1 DIALOGUE AUTHORING GUIDE
==================================================

This is the standalone VR dialogue system for Level 1.

Architecture:

Player Voice
↓
STT
↓
InputNormalizer
↓
NegotiationStateManager
↓
RuleBasedNPCBrain
↓
DialogueTableResponseProvider
↓
Character Dialogue File
↓
Subtitle/TTS

Important:
RuleBasedNPCBrain decides gameplay.
Dialogue files only decide wording.

Never change:
- prices
- accepted deals
- counters
- reputation values
- economy
- negotiation decisions

inside dialogue files.

==================================================
CURRENT STRUCTURE
==================================================

The current dialogue system uses:

- 23 scenario keys
- one character file per NPC
- one CharacterDialogueSet per NPC

Every current NPC has all 23 scenarios.

Very important:
- Every scenario must keep at least one unbucketed fallback line.
- Bucketed lines are optional dynamic flavor layers, not replacements for fallback lines.

That means:
- Unbucketed lines guarantee the NPC can always answer.
- Bucketed lines add mood/personality flavor when runtime buckets match.

==================================================
SCENARIO MEANINGS
==================================================

CustomerGreeting:
NPC arrives.

RepeatCustomerGreeting:
Returning customer.

AskWhatBuyerWants:
Player asks what the buyer wants.

AskBuyerBudget:
Player asks what price the buyer can offer.

AskQuantity:
Player asks what quantity the buyer wants.

SellerPriceTooHigh:
Player is seller and asks too much money.

SellerPriceSlightlyHigh:
Player price is high but close.

SellerPriceAccepted:
Buyer accepts seller price.

SellerPriceBelowExpected:
Seller offered a very cheap deal.

BuyerCounterFirst:
First negotiation counter.

BuyerCounterMiddle:
Middle bargaining.

BuyerCounterFinal:
Final offer.

BuyerHoldsFirm:
NPC refuses to move further.

PlayerAcceptedDeal:
Trade completed.

PlayerRejectedBuyerOffer:
Player refuses.

HistoryQuestion:
Historical or cultural questions.

SocialGreeting:
Hello or social talk.

OffTopic:
Anything unrelated.

UnclearSpeech:
STT failed or player meaning was unclear.

TransactionSuccess:
Successful ending.

TransactionFailure:
Failed negotiation.

TimePressure:
Low time or low patience.

Unknown:
Fallback.

==================================================
ASKQUANTITY WARNING
==================================================

AskQuantity means:
The player asked "what quantity?"

The NPC must answer the quantity they want to buy.

Correct:
"I need {quantityLabel} of {spiceName}."

Also correct:
"For my household, {quantityLabel} of {spiceName} will do."
"My order is {quantityLabel} of {spiceName}."

Wrong:
"How much {spiceName} is there?"
"Tell me the quantity first."
"How much are you selling?"

If you are editing AskQuantity lines, always make the NPC answer with:
- {quantityLabel}
- {spiceName}

==================================================
BUCKET STRATEGY
==================================================

Bucketed lines are optional dynamic flavor layers.

Current safe bucket strategy:

- desperationBucket should stay NpcDesperationBucket.Medium for now
- runtime desperation currently stays Medium
- Friendly NPCs can use patience High, Medium, or Low
- Strict NPCs should use patience Medium or Low only
- Normal NPCs should use patience Medium or Low only
- TimePressure bucketed lines should only use Low patience
- Use PlayerReputationBucket.Neutral unless you are intentionally writing reputation-specific lines

Current practical guidance:

Friendly NPCs:
- Abdul Rahman
- Lakshmi Amma
- Siddharth Chetti

Strict NPCs:
- Francisco de Almeida
- Chinappa Naik

Normal NPCs:
- Father Penteado

Avoid writing bucketed lines that current runtime cannot reach.

==================================================
HOW MATCHING WORKS IN PRACTICE
==================================================

Use unbucketed lines as the guaranteed fallback.

Then add bucketed lines only when you want extra flavor for:
- patience
- reputation
- round
- personality

Safe rule:
Write the fallback line first.
Then optionally add bucketed lines for the same scenario.

Do not rely on bucketed lines alone.

Important:

Even if the broader system once mentioned more placeholders, treat the list above
as the safe working set for current character dialogue writing.

==================================================
AUDIO PLACEHOLDER WARNING
==================================================

Human recorded audio cannot naturally speak dynamic placeholders unless handled separately.

Before sending dialogue lines for recording, decide which approach the project is using:

- placeholders are shown in UI only
- Android TTS speaks dynamic values
- modular recorded clips are used

Important:
Do not hardcode prices or quantities just to make recording easier.

Keep the authored text placeholder-safe first.
Recording strategy should be solved at the audio pipeline level, not by breaking dialogue logic.

==================================================
SAFE EDITING RULES
==================================================

When editing dialogue files:

- Do not change scenario keys
- Do not change bucket enum names
- Do not invent placeholders
- Do not change prices or decisions in dialogue files
- Prefer rewriting text only
- Keep voice lines short
- 1 sentence preferred
- maximum 2 sentences
- no modern slang
- no very long speeches

Good:
"That is costly, merchant. I can offer {counterPrice} {currency}."

Bad:
"I offer 50 varahas."

Reason:
Always use placeholders because the rule engine controls values.

==================================================
ADDING MORE LINES TO A CHARACTER
==================================================

The current character files use new DialogueLine(...) entries inside the
character Create() method.

You can extend a character in two safe ways:

1. Add more templates inside an existing DialogueLine
2. Add another DialogueLine for the same scenario with optional bucket filters

Example fallback line:

new DialogueLine(DialogueScenario.SellerPriceTooHigh, new[]
{
    "{offeredPrice} {currency} is too much, merchant.",
    "For {spiceName}, I can only offer {counterPrice} {currency}.",
    "Meet me closer to {counterPrice} {currency} and we have a deal."
}, "character_id")

Example bucketed flavor line:

new DialogueLine(
    DialogueScenario.BuyerHoldsFirm,
    new[]
    {
        "Enough delay. {currentBuyerOffer} {currency} is where I stand."
    },
    "character_id",
    PlayerReputationBucket.Neutral,
    NpcPatienceBucket.Low,
    NpcDesperationBucket.Medium,
    RoundBucket.Final,
    NpcPersonalityBucket.Strict)

==================================================
ADDING A NEW CHARACTER
==================================================

Step 1:
Create a new file in Characters/.

Step 2:
Return a CharacterDialogueSet with:
- character id
- display name
- personality bucket
- full list of DialogueLine entries

Step 3:
Register it in DialogueCharacterRegistry.cs.

Step 4:
Ensure the character has all 23 scenarios.

Step 5:
Ensure every scenario has at least one unbucketed fallback line.

Step 6:
If needed, add the character to any offline customer selection pools that rely on the registry.

==================================================
TESTING CHECKLIST
==================================================

Before considering dialogue changes done:

- Open Unity and check there are no compile errors
- Ask "how much" and confirm it maps to AskBuyerBudget
- Ask "what quantity" and confirm it maps to AskQuantity
- Confirm the NPC answers quantity, not asks for quantity
- Say "fifty" or "twenty eight" and confirm normalization turns them into numbers and the system reads them as PRICE
- Check Console for DialogueTable scenario logs and final reply logs
- Test at least one Friendly NPC
- Test at least one Strict NPC
- Test at least one Normal NPC

Good practical test set:
- Abdul Rahman or Lakshmi Amma or Siddharth Chetti
- Francisco de Almeida or Chinappa Naik
- Father Penteado

==================================================
GIT NOTE
==================================================

Before commit:

- stage the dialogue files you changed
- stage their .meta files if new files were created

Avoid accidentally staging unrelated changes, especially:

- unrelated deleted audio .meta files
- unrelated ground texture .meta files

If you are staging only dialogue work, double-check git status before commit.
